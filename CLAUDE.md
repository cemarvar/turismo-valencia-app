# Turismo Valencia (app Android)

App nativa para turistas, derivada de la web Turismo Valencia. Proyecto del TFG de DAM.

## Stack
- Kotlin 2.2 + Jetpack Compose (BOM 2026.02.01) + Material 3. AGP 9.4, compileSdk/targetSdk 37, minSdk 24.
- Arquitectura MVVM. Una pantalla = `Screen` + `UiState` + `ViewModel` (más un `Route` que los conecta; ver `docs/componentes.md`).
- Tipografía Source Sans 3 empaquetada en `res/font` (la app funciona sin conexión).
- **Mapa real: osmdroid 6.1.20** con teselas estándar de OpenStreetMap (el diseño las usa). Se descartó Google Maps SDK porque exige una clave dentro del APK. Las rutas a pie y en bici salen del servidor OSRM de OpenStreetMap Alemania (`routing.openstreetmap.de`, uso ligero) con respaldo aproximado si no responde. La ubicación usa `LocationManager` (sin servicios de Google). Los avisos de eventos (la mascletà) usan `AlarmManager` y notificaciones locales: sin servidor ni Firebase.
- Backend: la web ya publica las funciones `chat` (ValBot, Gemini; la clave vive en Netlify) y `api` (lectura de actividades, MySQL). ValBot de la app llama a `POST https://turismovalenciaa.netlify.app/api/chat` con OkHttp + corrutinas; si no responde, contesta con reglas. **`backend/` es el backend propio, en Supabase** (PostgreSQL gestionado en el esquema privado `app` + una función de borde `api-v1` en TypeScript, que es la única puerta; la app no lleva ninguna clave de Supabase, solo la dirección). Ofrece ofertas y reservas con escritura, está descrito en `docs/api.md`, **publicado en Supabase** (proyecto `turismo-valencia`, región UE; dirección base pública `https://rttqdgrrprzgdxdlhaeq.supabase.co/functions/v1/api-v1`) y probado en local y en la nube. **La app ya lee de ahí el catálogo de ofertas** (Retrofit, caché en Room y respaldo incluido en la app); **faltan las reservas reales** (ver `docs/progreso.md`).
- Dependencias en uso: Compose/Material 3, `material-icons-extended`, `navigation-compose`, `lifecycle-viewmodel-compose` + `lifecycle-runtime-compose`, `zxing-core` (código QR real de la reserva), `desugar_jdk_libs` (`java.time` en minSdk 24), `okhttp` 4.12 (ValBot y rutas; en tests, `mockwebserver` y `org.json`), **Retrofit 3.0.0** con `converter-kotlinx-serialization` y `kotlinx-serialization-json` 1.8.1 (la API propia; plugin `kotlin.serialization`) y **Room 2.8.5** con KSP 2.3.12 (`room-runtime`, `room-ktx`, `room-compiler`; el plugin `androidx.room` exporta el esquema a `app/schemas/`). **osmdroid** 6.1.20 (mapa; es Java y queda fuera de `packageScope`) y `core-splashscreen` 1.2.0 (pantalla de arranque del sistema). Solo para pruebas: `room-testing` (migraciones; necesita la 1.8 de `kotlinx-serialization-core`, que fija el `implementation` de `kotlinx-serialization-json`: ver el comentario de `app/build.gradle.kts`). Las demás (Coil…) se añaden en su fase, no antes.
- **Estado actual: frontend completo y funcional con datos en memoria.** Las 27 pantallas del Figma existen y navegan entre sí, y además todas las secciones de la web (Lo esencial, Planes, guías de entradas/tours/experiencias, textos legales y Contacto). El contenido sale de repositorios en memoria (`data/`) y de JSON en `assets/`, salvo **las ofertas (entradas, tours y experiencias), que vienen del servidor** (con caché en Room y, sin haber recibido nada, el catálogo incluido en la app); **lo del usuario (favoritos, descargas, reservas, ajustes, búsquedas recientes, avisos y «bienvenida ya hecha») se guarda en una base de datos Room** y sigue ahí al cerrar la app. ValBot sí habla con el servidor de la web (con respaldo por reglas); el **mapa es real** (OpenStreetMap, ubicación y rutas); los **avisos de eventos** (la mascletà, 30 min antes) son notificaciones locales reales con su permiso del sistema; la app tiene **icono propio** y la **pantalla de arranque del sistema**. No hay reservas en servidor ni mapa descargable por zonas (ver «Tags de pendientes»).
- **Contenido de la web**: `assets/web/index.json` + `assets/web/pages/<Pagina>.json` (65 páginas) y `assets/img/…` (443 fotos reducidas), generados desde el repositorio `cemarvar/TurismoValencia` con `tools/web-import` (ver su README). Se leen con `WebContentRepository`; las fotos se pintan con `PlaceImage(assetPath = …)`.

## Comandos
```bash
./gradlew assembleDebug        # compilar el APK de debug (en Windows: ./gradlew.bat; JAVA_HOME = jbr de Android Studio)
./gradlew test                 # tests unitarios (JVM)
./gradlew connectedDebugAndroidTest   # tests de Room en el emulador (desinstala la app al acabar: vuelve a hacer installDebug)
./gradlew lint                 # lint
cd backend && npm install      # una vez (la CLI de Supabase queda fijada en backend/package.json)
cd backend && npm start        # backend en local: Supabase en Docker (Docker Desktop en marcha); npm test = pruebas de la API; npm stop
adb reverse tcp:54321 tcp:54321 && ./gradlew installDebug -PapiBaseUrl=http://127.0.0.1:54321/functions/v1/api-v1/   # la app de depuración contra el backend local (con `npm start`); sin -PapiBaseUrl usa la nube
cd backend && npm run deploy   # publica en Supabase (migraciones + función; antes npm run login y npm run link); prueba de humo: API_BASE=<dirección base> python tests/test_api.py
graphify update .              # refresca el grafo de conocimiento local del código (graphify-out/, ignorado por git; sin LLM); consultas: graphify query "…" · explain "X" · path "A" "B" · god-nodes
```

## Depurar una pantalla desde adb
En builds de depuración `MainActivity` acepta extras para saltarse la bienvenida:
```bash
adb shell am start -n com.cmarcillovargas.turismovalencia/.MainActivity --es route detalle/mercado-central
# otros extras: --ez offline true (simula sin conexión) · --ez emptyFavorites true (vacía los favoritos)
#               --ez chatFake true (ValBot contesta como Gemini sin llamar al servidor)
#               --ez resetData true (vuelve a los datos de demostración; pásalo siempre, que lo guardado persiste entre arranques)
#   ubicación: `adb shell pm grant|revoke <paquete> android.permission.ACCESS_FINE_LOCATION` y `adb emu geo fix -0.3755 39.4745` (longitud latitud)
#   notificaciones: `adb shell pm grant|revoke <paquete> android.permission.POST_NOTIFICATIONS`; alarma programada: `adb shell dumpsys alarm` (busca el paquete);
#   para ver saltar un aviso: `adb shell settings put global auto_time 0` y `adb shell cmd alarm set-time <milisegundos UTC>` (al terminar, `set-time` con la hora real y `auto_time 1`)
```
Rutas: `inicio`, `mapa`, `valbot`, `favoritos`, `reservas`, `busqueda`, `categoria/que-ver`, `detalle/<id>`, `entradas?tab=experiencias`, `sostenible`, `ruta/<id>`, `reservar/<offerId>`, `reserva/seed-1`, `descargas`, `perfil`, `notificaciones`, `contacto`, `pagina/<Pagina>` (p. ej. `pagina/Navidad`, `pagina/AvisoLegal`). Para comparar con el Figma: emulador a 780×1688 px / 320 dpi (`adb shell wm size 780x1688`, `wm density 320`) = 390×844 dp; al terminar, `wm size reset` y `wm density reset`.

## Pruebas
`tools/verify/` comprueba contra la web que están todas las páginas, índices, fotos y enlaces, y en el emulador que cada chip, sección, tarjeta y guía abre lo que debe y que cada tarjeta muestra su foto. Ejecútalas tras tocar contenido, navegación o imágenes (`python tools/verify/verify_data.py`, `verify_live.py`, `verify_ui.py`, `verify_img.py`). Los tests unitarios (`./gradlew test`) cubren el cliente de ValBot (con `MockWebServer`), el respaldo por reglas, las fichas que enlaza una respuesta, el Markdown del chat y el paso de las filas de Room a los modelos; los instrumentados (`connectedDebugAndroidTest`) cierran y reabren la base de datos para comprobar que todo lo guardado persiste. `verify_ui.py persist` hace lo mismo desde la interfaz. `verify_release.py` prueba la versión de publicación (R8) en el emulador: arranque, Room, ValBot, mapa, ruta y una reserva. `verify_ui.py mapa` prueba el mapa, la ubicación (permisos reales), la ruta y el modo sin conexión. `verify_ui.py avisos` prueba los avisos de eventos con el permiso real del sistema (diálogo, «No permitir» dos veces → «Abrir ajustes»), las alarmas (`dumpsys alarm`), el disparo adelantando el reloj, tocar la notificación con la app cerrada, el reinicio del móvil y la redirección a Ajustes de ubicación y notificaciones. Los tests instrumentados incluyen la migración de Room (`MigrationTest`, hasta la v3), los avisos (`RemindersTest`) y el catálogo de ofertas con una base en memoria y un servidor falso (`OffersTest`). `OffersApiTest` (MockWebServer) y `OfferMappingTest` leen los ejemplos de `backend/contract/examples/`, y `verify_ui.py ofertas` prueba el catálogo en el emulador con el servidor real (llega y se guarda con su versión, 304 al reabrir, sin conexión desde la caché o el catálogo incluido).

`backend/tests/test_api.py` (`cd backend && npm test`, con el backend local en marcha) prueba la API por HTTP: ofertas y ETag, reservas, idempotencia, validaciones, aforo con peticiones simultáneas, límites de peticiones, recuperar por localizador y correo, que la base de datos queda cerrada a la clave pública y que las respuestas siguen la forma de los ejemplos del contrato. Contra la nube solo hace lecturas (`API_WRITES=1` para crear reservas de prueba).

## Convenciones
- **MVVM + state hoisting**: el `ViewModel` expone un `UiState` inmutable; los composables reciben estado y callbacks, no el `ViewModel`.
- **Nada hardcodeado en las pantallas**: ni colores (`MaterialTheme.colorScheme.*` o `MaterialTheme.appColors.*`), ni tipografías (`MaterialTheme.typography.*`), ni formas (`MaterialTheme.shapes` o `CardShape`/`BottomSheetShape`/`PillShape`), ni espaciado (`Spacing.*`), ni textos. Las medidas propias de una pantalla van como constantes privadas con nombre («Medidas del diseño»).
- **Reutilizar antes de crear**: mira `docs/componentes.md`; si falta una variante, amplía el componente existente y actualiza ese documento.
- **Color**: el naranja de marca `#EB5A00` solo para iconos y gráficos (`appColors.brand`, 3,5:1). Texto y botones usan `primary` = `#C44D00` (4,76:1). No usar la paleta del modo «MD3 · Prompt».
- **Textos** en `res/values/strings.xml`, solo español por ahora (`TODO(i18n)`). Excepción: textos de muestra de `@Preview`.
- **Eyebrows**: `MaterialTheme.typography.eyebrow` y el texto con `.uppercase()`.
- **Ninguna clave viaja en el APK**: ni API keys (Gemini incluida), ni contraseñas, ni tokens, ni en el código, ni en `strings.xml`, ni en `BuildConfig`. Viven solo como variables de entorno del backend. `local.properties` y `.env` no se suben a git.
- **Fotos de la web**: nunca como `R.drawable`; van en `assets/img/<ruta de la web>` y se piden con `PlaceImage(image = null, …, assetPath = ruta)` (si el archivo no existe se pinta el fondo con el icono de la sección). Las fotos del diseño (`.fig`) siguen siendo `R.drawable` y tienen prioridad.
- **Datos**: las pantallas nunca leen los `Fake*` directamente ni los DAO; piden al repositorio de `AppContainer` desde su `ViewModel` (`containerFactory { MiViewModel(it) }`). Los repositorios de lo del usuario exponen `StateFlow` ya cargados y escriben en Room (la interfaz se actualiza cuando la tabla cambia). El backend solo cambia los repositorios: las ofertas ya vienen del servidor (`OffersRepository`: Room como caché, `FakeOfertas` como respaldo y las fotos del diseño asociadas por `id`) y las reservas llegarán igual.
- **Mapa**: toda ficha con `onMap = true` lleva `location = LatLon(lat, lon)` (WGS84; lo exige un `require` en `ContentItem` y lo comprueba `ContentCoordinatesTest`). `OsmMap` pinta los marcadores como imágenes (los dibuja `PinRenderer` con los gráficos de Compose) y una capa invisible les pone nombre para accesibilidad: si se mueve el mapa o cambia de tamaño hay que llamar a `camera.moved()`. **Atribución obligatoria**: mostrar `MapAttribution` en toda pantalla con teselas de OpenStreetMap. Las distancias de las fichas con distancia en el diseño salen de sus coordenadas y de `ContentRepository.origin` (ubicación del usuario o, fuera de Valencia, Plaza del Ayuntamiento); los `ViewModel` que las muestran combinan `content.origin` para recalcular.
- **R8 (release)**: `app/build.gradle.kts` limita R8 con `packageScope` (`androidx`, `kotlin`, `kotlinx`, `okhttp3`, `okio`, `retrofit2`). Si una librería de Kotlin queda fuera, R8 fija miembros de `kotlin.text` y la app se cierra al abrir (`IllegalAccessError … kotlin.text`), cosa que la versión de depuración no avisa. **Al añadir una dependencia de Kotlin (Coil…), incluir su paquete en `packageScope`** y pasar `tools/verify/verify_release.py` con el APK de publicación firmado con la clave de depuración.
- **Room**: cambiar una entidad exige subir `version` en `AppDatabase`, escribir la migración (en `AppDatabase.Migrations`, nunca `fallbackToDestructiveMigration`: es lo que el usuario guardó), probarla en `MigrationTest` y volver a generar `app/schemas/` (se commitea). Versión actual: 3 (v2 añade `reminders`; v3 añade la caché de ofertas del servidor, `offers` y `cache_meta`, que se puede vaciar sin perder nada del usuario). Los datos de demostración (`DemoData`) solo se insertan al crear la base de datos.
- **Notificaciones**: el permiso (Android 13+) se pide **en contexto**, cuando el usuario enciende un aviso o el interruptor de Notificaciones (`rememberNotificationAccessRequest`), nunca al abrir la app: por eso el canal no se crea hasta que sale el primer aviso (crearlo antes hace que Android 13 pregunte al arrancar). Un aviso llega si el usuario lo pidió, el ajuste general está activo y el sistema permite notificar (`RemindersRepository.active`); los interruptores muestran ese estado real (en Android 13+ el de Fallas sale apagado hasta que el usuario da el permiso). Las alarmas son ventanas de 10 min que acaban 30 min antes del acto (`setWindow`, sin el permiso de alarmas exactas); la hora se calcula siempre en la hora de Valencia. Si el sistema ya no deja preguntar, se ofrece `OpenSettingsDialog`. Un aviso nuevo se añade a `EventReminders` y no necesita tocar nada más.
- **Backend (`backend/`)**: la base de datos está **cerrada** (esquema `app` no expuesto, seguridad por filas sin políticas, sin permisos para `anon` ni `authenticated`) y solo la entra la función `api-v1`; las reglas (validar, idempotencia, plazas, precio, localizador) y la forma del JSON viven en funciones SQL dentro de una transacción, y la función solo traduce HTTP. Las migraciones publicadas **nunca se editan** (se añade otra). Dinero en céntimos. Sin cuentas: `X-Device-Id` (UUID del móvil) e `Idempotency-Key` (UUID por intento). Los ejemplos de `backend/contract/examples/` son el contrato: la app los lee en sus pruebas (`OffersApiTest`, `OfferMappingTest`) y el servidor comprueba que sigue respondiendo con esa forma. Ningún secreto en el repositorio (contraseña de la base de datos solo en el gestor de contraseñas y en variables de entorno).
- **Accesibilidad**: áreas táctiles ≥ 48dp (`MinTouchTarget`); `contentDescription` en imágenes informativas y `null` en iconos decorativos junto a un texto.
- Solo tema claro (`TODO(dark)`).
